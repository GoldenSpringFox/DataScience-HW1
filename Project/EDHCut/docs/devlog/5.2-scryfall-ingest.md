# Task 5.2 — Scryfall ingest + name resolution table
Date: 2026-07-29 | Status: done

## Goal & hypothesis
Populate `cards` and `card_names` from the Scryfall `oracle_cards` bulk file: one row per
commander-legal card, plus every alias (full name, individual DFC/split/adventure face
names, normalized variants) that the future decklist parser (task 7.1) will need to resolve
free-text card names to `oracle_id`.

## Data
- Source: `api.scryfall.com/bulk-data`, `type == "oracle_cards"`, fetched live 2026-07-29.
- Downloaded: 23.2 MB compressed (gzip JSONL — see Impediments; the plan's Appendix A figure
  of 179.8 MB was for the old uncompressed-JSON format).
- Bulk file: **38,374** card objects total.
- After filtering to `legalities.commander == "legal"`: **31,622** cards kept (≈82% of the
  bulk file). **Was 30,574 in the original version of this run** — see "Correction" below;
  the original filter also required `"paper" in games`, which wrongly excluded 1,048 real,
  commander-legal cards and was removed.
- `card_names`: **33,220** normalized aliases for those 31,622 cards (the excess over 1:1
  comes from multi-face cards contributing one alias per face in addition to the combined
  full name).
- `0` cards skipped for missing `oracle_id` in this run (the `reversible_card`/`art_series`
  layouts that lack one didn't appear in the commander-legal subset this bulk file happened
  to contain — code path exists and is exercised by nothing right now, worth re-checking
  after a future refresh).
- Verified zero duplicate full names among the kept cards (no alias-collision risk from two
  different oracle_ids sharing a display name).

## Correction (found during task 5.3-B, applied retroactively here)
The original filter was `legalities.commander == "legal"` **AND** `"paper" in games`. The
`games` field lives on the *representative printing* Scryfall's `oracle_cards` bulk file picks
for each `oracle_id` — for cards later reprinted MTGO-only (the "Masters Edition" series:
ME1–ME4, Vintage Masters), that representative printing can be the digital one even though the
card has real paper prints going back decades. Confirmed via Scryfall's search API: Tundra
(an original dual land), Palinchron, Wheel of Fortune, Goblin Chirurgeon, Strip Mine, Lotus
Petal, and 1,042 others all have real paper printings and `legalities.commander == "legal"`,
but their bulk-file representative printing was an MTGO-only reprint — the `games` check
silently dropped every one of them. Root-caused after noticing that Archidekt decks harvested
in task 5.3-B were flagging well-known, clearly-legal cards as "illegal" (initially assumed
these were banned/restricted cards — the user caught the mistake and asked for verification
by name for a specific card, which is what surfaced this).

`legalities.commander` alone turned out to be sufficient without the `games` check:
Scryfall computes it against the Commander Rules Committee's paper-based legal pool
regardless of which specific printing got chosen as representative, and genuinely
digital-only cards (Alchemy rebalances, e.g. `A-Acererak the Archlich`) correctly report
`commander: "not_legal"` on their own — verified this holds via Scryfall's search API before
committing to the fix, not assumed. `is_paper()` was removed from `edhcut/ingest/scryfall.py`
entirely; see its module docstring for the permanent record of this reasoning.

Re-ran the ingest after the fix: 30,574 → **31,622** cards (exactly +1,048, confirming the
fix's scope matched the diagnosis precisely), 32,174 → **33,220** aliases. Also cleared
`decks`/`deck_cards` rows that had been harvested (during 5.3-B testing) against the old,
incomplete `cards` table, so no stale data carries forward.

## Method & design decisions
- **Row-oriented over pandas**: unlike the source notebook (`Analysis/EDHDataAnalysis.ipynb`),
  this ingest processes cards as plain dicts and writes directly via `sqlite3.executemany`,
  not through a pandas DataFrame. The target is the SQL schema's exact column shape (JSON
  arrays as TEXT, real booleans), not an analysis-ready DataFrame — going through pandas would
  mean fighting its dtype inference (NaN vs `None`, nullable-boolean extension types) just to
  convert back out again for SQL.
- **Multi-face fallback**: `oracle_text`/`mana_cost` are frequently `NULL` at the top level for
  transform/split/adventure layouts (confirmed against the notebook's own missing-value
  report: 2.7%/1.6% of the corpus) — the real content lives in `card_faces`. Both fields fall
  back to `" // "`-joined face values when the top-level field is empty, so downstream text
  mining (task 6.5) always has something to parse for these cards.
- **`can_be_commander`**: `Legendary` + `Creature` in `type_line`, OR `"can be your commander"`
  (case-insensitive) anywhere in the resolved oracle text — catches Backgrounds, commander
  planeswalkers, and similar "can be your commander" grants without a hardcoded card list.
- **Name normalization** (`normalize_name`): lowercase → explicit `æ→ae`/`œ→oe` substitution
  (these don't decompose under NFKD — they're atomic Unicode letters, not composed accents) →
  NFKD decompose + drop combining marks (handles `Jötun Grunt` → `jotun grunt`) → collapse
  everything non-alphanumeric to single spaces. Chose a single normalization function applied
  uniformly to every alias (full name + each face name) over maintaining a separate list of
  "punctuation-stripped variants" — simpler, and produces the same result.
- **Idempotency via upsert, not replace-all**: both `cards` and `card_names` use
  `INSERT ... ON CONFLICT DO UPDATE` keyed on `oracle_id` / `name_normalized`. Considered
  `DELETE FROM cards` + reinsert (simpler to reason about, and what "idempotent" most directly
  suggests) but rejected: by the time this ingest is re-run as part of a refresh (task 8.4),
  `deck_cards`/`card_tags`/`edhrec_card_stats` will hold foreign keys into `cards`, and
  `PRAGMA foreign_keys = ON` (set in `db.py`) would reject deleting a still-referenced row.
  Upsert accepts one known gap in exchange: a card that *loses* commander legality between
  runs stays in the table with stale data instead of being removed. Filed under Notes for
  future work.
- `ingest_log.unresolved` is repurposed here to mean "cards skipped for having no
  `oracle_id`" — the closest analog available in this ingest, since there's no external name
  to resolve yet at this stage (this table IS the resolution source for everything after it).

## Interesting findings
- The em-dash in `type_line` (e.g. `Legendary Creature — Goblin Warrior`) printed as `�` when
  inspected via a raw `python -c "print(...)"` on this Windows shell — turned out to be purely
  a `cp1252` console-encoding artifact (`sys.stdout.encoding`), not stored corruption:
  `repr()` and a round-trip through a UTF-8 file both confirm the real U+2014 character is
  correctly in the database. Worth remembering for later devlog sessions on this machine —
  don't diagnose encoding bugs from what the terminal prints.

## Impediments
- **Scryfall's bulk-data API has moved since the plan's 2026-07-19 investigation** (10 days
  before this task ran): the `/bulk-data` index no longer returns `download_uri`/`size` for
  any bulk type (checked all 7: `oracle_cards`, `unique_artwork`, `default_cards`,
  `all_cards`, `rulings`, `art_tags`, `oracle_tags`) — it's `jsonl_download_uri` +
  `compressed_size` uniformly now, pointing at gzip-compressed JSONL instead of a plain JSON
  array. Handled by downloading the `.gz` file and parsing it line-by-line
  (`gzip.open(..., "rt")` + one `json.loads` per line) instead of `pd.read_json` on a whole
  array. Net effect is positive — 23.2 MB compressed vs. the old 179.8 MB uncompressed, and
  JSONL is naturally streamable if memory ever becomes a concern. **This affects task 5.5
  (Tagger bulk) too** — same index, same field names, so 5.5 should use `iter_bulk_cards`-style
  line parsing from the start rather than rediscovering this.

## Notes for future work
- Upsert-not-delete (see Method) means a card that drops out of `legal_commander` between
  refreshes isn't removed from `cards`. Low risk at current scope (bans are rare) but the QA
  report (task 5.6) should probably cross-check `cards` against a fresh bulk fetch for
  staleness once refreshes are routine.
- The `oracle_id`-missing skip path (`reversible_card`/`art_series` layouts) is untested
  against real data — zero occurrences in this run's commander-legal subset. Fine for now;
  flag if a future refresh ever reports `skipped_no_oracle_id > 0` unexpectedly.
- General lesson from the `games`/paper bug: don't trust a single-representative-printing
  field from `oracle_cards` for anything that's really a property of "has this card ever
  existed in some form" rather than "what does this one printing look like." `legalities.*`
  and similar computed/aggregate fields are safe; `games`, `set`, `collector_number`, etc.
  describe the one chosen printing and can be misleading for older/heavily-reprinted cards.
- `iter_bulk_cards()` in `edhcut/ingest/scryfall.py` is generic (gzip JSONL → dict generator)
  and reusable as-is for task 5.5's `oracle_tags` bulk file.
