# Task 5.3 QA — precon table + `decks.precon_similarity`
Date: 2026-07-29 | Status: done

## Goal & hypothesis
Plan §6 task 5.3-B calls for computing `decks.precon_similarity` for commander slots whose
commander shipped in an official precon (Kyler, Sigardian Emissary named specifically) —
Jaccard overlap between each harvested deck and the official precon list, needed for the
precon-contamination test (plan §1: "the corpus will be full of barely-modified precon lists,
and the tool must not just parrot precon contents"). Two pieces: (1) a reference table of
every official precon and its card list, (2) the similarity computation itself.

## Data

### `precons` / `precon_cards`
- Source: `archidekt.com/commander-precons`, Archidekt's own curated index (owner account
  "Archidekt_Precons"). Same `__NEXT_DATA__`-embedded-JSON technique as deck search
  (`docs/archidekt_api.md` §2.2), but the payload here is a ready-made
  `{set_name: [listing, ...]}` dict at `props.pageProps.precons` — no pagination needed.
- **179 official precon decklists** across **49 sets**, spanning Commander 2011 through
  sets released in the last 30 days. Each listing's `id` is a normal Archidekt deck id,
  fetched the same way as any other deck.
- Harvest result: **179/179 kept, 0 errors**, **14,759 card rows written**, only **2**
  unresolved oracle_ids across the whole corpus (vs. tens of thousands of decks' worth of
  banned/restricted-card noise in the main harvester — precons are curated, clean data).
- **174 precons declare 1 commander, 5 declare 2** (Doctor Who's 3 Companion+Doctor pairs,
  the Zndrsplt/Okaun Secret Lair, and Food and Fellowship's Sam/Frodo) — `partner_oracle_id`
  is genuinely needed, not a partner-slot-only concern.
- Every sampled precon's card list sums to exactly **100** qty (commander(s) included — see
  Method below for why, unlike `deck_cards`).
- Design decision confirmed with the user before building: card list includes the
  commander(s) rather than excluding them, since precons often ship several legendaries in
  the box's color identity as genuine alternative-commander options, and "what physically
  came in the box" shouldn't change based on which one gets picked.

### `decks.precon_similarity`
- Ran against the full 1,230-deck corpus (all 5 commander slots as of this writing).
- **601/1230 decks matched a precon** (commander shipped in one, declared or as an
  alternative) — this split out to be **exactly** the Krenko slot (301/301) + Kyler slot
  (300/300); Yenna (0/300), Orysa (0/29), and Yoshimaru+Bruse Tarl (0/300, including its 296
  partner-fallback decks running Kediss/Jeska/Rograkh/Akiri/Ardenn/etc.) matched nothing.
- **Kyler distribution** (n=300): min=0.031, p25=0.132, median=0.186, p75=0.263, max=0.949,
  mean=0.217. Bucketed: 20 decks <0.1, 145 in [0.1, 0.2), 82 in [0.2, 0.3), 44 in [0.3, 0.5),
  8 in [0.5, 0.9), **1 above 0.9** (0.949 — deck `2358272`, essentially an unmodified precon
  copy). Matches the plan's expectation of a corpus "full of barely-modified precon lists"
  at the tail, with the bulk of the corpus meaningfully diverged.
- **Krenko distribution** (n=301): min=0.073, max=0.322, mean=0.189 — much flatter, no
  near-1.0 outlier. Expected: Krenko was never a precon's own *declared* commander, only an
  *alternative* inside the mono-red "Goblin Storm Secret Lair Commander" precon (deck
  `22357696`), so the overlap here reflects two independent goblin-tribal builds converging
  on the same staples, not literal precon-copying.

## Method & design decisions

**Matching a deck to a precon is per-deck, not per-slot.** A deck's own `commander_oracle_id`
/ `partner_oracle_id` (its *real* commanders — task 5.3-B's partner fallback means these can
differ from the slot's nominal commander) is checked against every precon's declared
commander, declared partner, and `alternative_commander_oracle_ids`. This is what makes the
Kyler case work at all: Kyler never shipped as any precon's own printed commander, only as an
alternative inside "Coven Counters" (declared commander Leinore, Autumn Sovereign, both GW,
deck `2209041`) — confirmed live before writing any matching code.

**Best-match, not first-match.** A deck can match more than one precon (a card reprinted as
an alternative across sets); `precon_similarity` takes the highest Jaccard across all matches,
since the question is "is this basically a copy of *some* precon," not of one arbitrarily
chosen one.

**Similarity is Jaccard over distinct `oracle_id` sets, not quantities.** 15 vs. 20 Mountains
counts as a full match on "Mountain" — this measures card-*selection* similarity, matching
the plan's framing ("barely-modified precon lists"), not exact physical-copy similarity.

**Symmetric commander exclusion — the one non-obvious design decision.** `deck_cards` already
excludes a deck's own commander(s) (task 5.3-B). The precon side needs the *same* deck's
commander(s) subtracted too, not just the precon's own *declared* commander(s) — otherwise a
card like Krenko, which is only an *alternative* in its matched precon, would still count as
a "missing" card on the deck side (it can structurally never appear in `deck_cards` since it's
the deck's own commander) while remaining present as an ordinary card on the precon side,
artificially deflating every Krenko-slot deck's similarity. Caught by a test
(`test_compute_deck_precon_similarity_excludes_deck_commander_from_both_sides`) before ever
running against real data.

**`None`, not `0.0`, for "no precon matches at all."** `jaccard_similarity()` returns `None`
when both sides are empty (nothing to compare) — kept distinct from a confirmed `0.0`
(compared, and genuinely no overlap) so a Yenna/Orysa deck's `NULL` can't later be misread as
"measured zero contamination."

**Backfill always recomputes every row it touches, including back to `NULL`.** Re-running
after a `precons` re-harvest (a set gets pulled, alternatives change) shouldn't leave a stale
similarity value behind for a deck that no longer matches anything.

## Evaluation & results
Verified before trusting the output:
- Every sampled precon sums to exactly 100 qty (structural sanity on the harvest).
- 0 precons have a declared commander leaking into their own `alternative_commander_oracle_ids`.
- Match counts split exactly along slot boundaries (301 + 300 = 601), which is a strong
  signal the per-deck matching logic isn't accidentally over- or under-matching — no
  partial/partial slot would be expected by chance.
- `pytest`: 15 new tests across `test_precons.py` / `test_precon_similarity.py` (73 total in
  the package), covering commander/partner/alternative matching, the symmetric-exclusion
  case, best-of-multiple-matches, `None` vs. `0.0`, idempotent re-harvest, scoped backfill,
  and one-bad-listing-doesn't-abort-the-run.

## Interesting findings
- The original plan named only Kyler as a known precon-shipped commander. Building
  `alternative_commander_oracle_ids` generically (rather than hardcoding Kyler's case)
  surfaced a second real match — Krenko, Mob Boss, as an alternative in a Secret Lair
  precon — with no extra code needed. Worth keeping in mind if more commander slots are
  added later: this check now runs for free on every slot.
- Kyler's `cardName=`-based precon-adjacent lineage produced a genuinely bimodal-looking
  distribution: a long, low tail (players who kept the Leinore-flavored precon shell but
  swapped the commander) and a sharp single outlier at 0.949 (a copy in all but name).
  Krenko's distribution has no such outlier — consistent with Krenko never actually being
  *the* precon's commander, just convergent deckbuilding.

## Impediments
- First debugging mis-step, not a real bug: checked "did Kyler get an alternative-commander
  match" with `alternative_commander_oracle_ids LIKE '%kyler%'` against the DB — the column
  stores JSON arrays of oracle *UUIDs*, not names, so the query silently matched nothing.
  The data was correct the whole time; re-checked properly via `json.loads()` and confirmed
  Kyler + Sigarda, Heron's Grace both listed for precon `2209041`.
- Locating Kyler's own precon by guessing set names failed twice (checked Battle for
  Baldur's Gate and Kaldheim Commander, both wrong) before cross-referencing Scryfall's own
  `set`/`set_name` fields for the card directly — Kyler is from Midnight Hunt Commander
  (`mic`), and even there it's not the deck's declared commander (Leinore is), which is
  exactly the case this whole feature exists to handle.

## Notes for future work
- `alternative_commander_oracle_ids` and the matching logic are commander-count-agnostic —
  if a 3rd/4th commander mechanic is ever harvested (Background, or more partner pairs),
  no changes needed here.
- Not yet wired into any downstream scoring (task 6.1's planned "down-weight near-duplicate
  decks" per plan §6, task 6.1 prompt) — `decks.precon_similarity` is populated and ready for
  that consumer, but the weighting logic itself is out of scope for this task.
