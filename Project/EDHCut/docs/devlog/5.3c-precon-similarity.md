# Task 5.3 QA — precon table + `decks.precon_similarity`
Date: 2026-07-29 | Status: done

Harvested a reference table of official precons (**179** decks across 49 sets, 14,759 card
rows) and computed `decks.precon_similarity` — best-match Jaccard between each deck and any
precon its commander shipped in. **601/1230** decks matched (exactly the Krenko + Kyler slots).

## Decisions
- Precon card lists **include** the commander(s): "what physically came in the box" shouldn't
  change based on which legendary the player ends up picking.
- Matching is per-deck and checks declared + partner + **alternative** commanders. Kyler only
  ever shipped as an alternative (inside Coven Counters, declared commander Leinore), so
  declared-only matching would have found nothing.
- Commander exclusion is **symmetric** — the deck's own commander is subtracted from the precon
  side too, otherwise alternative-commander cases deflate every score in the slot.
- `None` (no precon matched at all) kept distinct from `0.0` (matched, genuinely no overlap).
- Backfill recomputes every row it touches, including back to `None`, so a re-harvest can't
  leave stale values behind.

## Bugs
- None. One false alarm: `alternative_commander_oracle_ids` stores oracle UUIDs, not names, so
  a `LIKE '%kyler%'` probe matched nothing — the data was correct the whole time.

## Outcome
Done, 15 new tests. Kyler shows the expected precon-copy tail (max 0.949, one near-identical
copy); Krenko's distribution is flat — convergent goblin builds, not copying, since it was
only ever an alternative commander. Not yet consumed by task 6.1's deck weighting.
