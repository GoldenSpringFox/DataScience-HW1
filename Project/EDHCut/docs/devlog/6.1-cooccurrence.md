# Task 6.1 — Co-occurrence & association scores
Date: 2026-08-02 (color-conditioned t-score added 2026-08-12) | Status: done

First module of `edhcut/analysis/`: sparse card×card co-occurrence (global + per-slot) plus
smoothed PMI and lift, saved as `.npz`/`.parquet` under `data/kb/dev/`. Card pool = cards in
≥3 decks (3,095 of 31,622 at the time).

## Decisions
- One shared `oracle_id`-ascending card index across the global matrix and every per-slot
  matrix, so all scopes share row numbering.
- **Precon down-weighting is continuous**, not the plan's grouping/capping: full weight below
  0.9 similarity, linear decay to a 0.1 floor at 1.0. Needs no notion of which decks duplicate
  *each other*. Only 1 of 1,230 decks exceeds 0.9 — the scheme is real but barely load-bearing
  at this corpus size.
- Lift is deliberately left undiscounted (a plain "times more than chance" for eyeballing);
  PMI is the smoothed, discounted score downstream steps consume.
- `CooccurrenceResult` keeps both raw and weighted pair counts — the mask needs raw, the
  probability estimate needs weighted.

## Bugs
- **PMI produced ten-way ties of unrelated cards.** Before discounting, Purphoros's top-10 was
  ten random cards at *exactly* +0.492. Cause: when a rare card co-occurs with the query in
  every deck it appears in — easy by chance at 3–30 decks — smoothed PMI reduces algebraically
  to a constant independent of that card's own count, so coincidences tie at the ceiling and
  drown out well-supported pairs. `min_pair_count=3` doesn't touch this. Fixed with Pantel/Lin
  discounting (<5% change on a 50-deck pair, collapses low-count pairs). This is the plan's
  "small-corpus PMI noise" risk firing from one *side*'s small count.
  Worth remembering: unit tests on formula mechanics all passed — only the qualitative eyeball
  check caught it.
- **The pooled null model has no notion of color-identity legality** (found during 6.3's
  notebook review): two unrelated same-color cards read as associated purely because they share
  a legality-restricted pool. Fixed with `compute_color_conditioned_tscore`, mirroring
  `playrate.py`'s eligible-deck logic:
  ```
  N_i  = decks eligible to run i;  N_ij = decks eligible to run both
  p_i  = marginal_i / N_i   (this is playrate.py's play_rate)
  t_color = (joint - N_ij * p_i * p_j) / sqrt(joint)
  ```
  **Self-validating**: when either card is colorless the formula reduces algebraically to the
  pooled t-score — confirmed at exactly 0.0% change on every colorless pair, proving the
  correction only fires where a real color gap exists. Validated on 20 real pairs: genuine
  same-color synergies move 0 to −8% (Goblin Warchief + Skirk Prospector −16%, Cultivate +
  Kodama's Reach −35%), while generic same-color pairs collapse 71–92% (Swords + Felidar
  Retreat −92%), some flipping negative.
- `scipy` wasn't in the shared venv; added `numpy`/`scipy` to `pyproject.toml`.

## Outcome
Done, 20 tests (10 more for the t-score). Post-fix eyeball check: `Cultivate` → `Kodama's
Reach` at the top globally — the pairing the plan set as *task 6.2's* success criterion,
already recovered from co-occurrence alone. Krenko's `Skirk Prospector` surfaces a recognizable
sac-outlet package.

Open items:
- Color-conditioning is **not** wired into PMI/lift (same pooled-null shape, likely same bias)
  or `top_associated`.
- Genuine cross-color synergies are barely represented in the corpus at all (test pairs shared
  0–1 decks across 13,207) — the harvest was built for commander breadth, not color-pair depth.
- Orysa's 29-deck corpus clears the `min_pair_count` floor at a *higher* rate than the big
  slots, which suggests the floor under-protects thin corpora rather than protecting them.
- `cooccur_<scope>.npz` persists only the weighted counts; raw counts exist transiently and
  would need re-deriving from `deck_cards` to audit the down-weighting after the fact.
- Note for anyone eyeballing: commanders are structurally absent from every matrix, since
  `deck_cards` excludes them — looking one up correctly raises.
