# Task 5.6 — QA & coverage report
Date: 2026-07-31 | Status: done

Cross-source sanity report over everything 5.2–5.5 harvested, as both a markdown report
(`edhcut/ingest/qa_report.py`) and the course EDA notebook (`notebooks/01_data_overview.ipynb`).
No new harvesting.

## Decisions
- Unresolved-name data was never persisted queryably by the three ingest modules, so this
  re-derives it from what's already on disk (audit log text, cached EDHREC session, the
  unfiltered Scryfall bulk file) rather than retrofitting three schemas for a one-off report.
- The notebook calls `qa_report.py`'s functions directly, so chart numbers match the report by
  construction rather than by keeping two implementations in sync.
- `plotly`/`jupyter` went into a `notebooks` extras group, not core dependencies.

## Bugs
- **Deck-size check produced 23 false positives.** `deck_cards` deliberately excludes
  unresolved (now-banned) cards, so a legitimate deck stores shorter than 99/98. Fixed by
  reconciling against each deck's own unresolved count from the audit log. The 2 survivors are
  real: decks with **more than 2** `"Commander"`-tagged cards (Partner-with/Background chains),
  which `decks.partner_oracle_id` structurally can't represent — a schema edge case, verified
  not to be corrupt data.
- **Comma-in-card-name parser bug.** The audit log joins unresolved names with `", "`, which is
  indistinguishable from a comma inside a name ("Orcrist, Goblin-cleaver"). A naive split
  produced fake half-names; fixed by greedily re-merging fragments that match a real Scryfall name.
- Notebook-only: `connect(db).__enter__()` without holding the context-manager object let GC
  close the connection mid-notebook. Hold the object, exit it explicitly in the last cell.

## Outcome
Done, 124/124 tests, notebook executes end-to-end with 0 errors. 1,230 decks, no genuine size
violations, all fixture decklists resolve. EDHREC-vs-Archidekt top-10 overlap is 10/10 for
Krenko down to 2/10 for Yoshimaru+Bruse Tarl — the low one is expected, since that slot is
mostly fallback decks running a different real second commander.

Notably, the report's first catches were two bugs in its own supporting code, both artifacts of
how earlier tasks logged things — not data-quality problems with the harvest.
