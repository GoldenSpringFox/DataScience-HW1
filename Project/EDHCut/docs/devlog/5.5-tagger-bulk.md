# Task 5.5 — Scryfall Tagger bulk tags
Date: 2026-07-31 | Status: done

Populated `card_tags` (`source='tagger_bulk'`) from Scryfall's `oracle_tags` bulk file, with
ancestor tags expanded through the hierarchy. Live run: **376,800 rows, 99.4% of cards tagged**.

## Decisions
- Ancestor expansion walks `parent_ids` iteratively with a visited set — the hierarchy is a
  real DAG, not a tree, so both diamonds and malformed cycles need guarding.
- Taggings whose `oracle_id` isn't in our `cards` pool are skipped and counted, not attempted —
  Tagger covers all of Magic, our pool is commander-legal only.
- Extracted `expand_taggings()` as a pure function so hierarchy expansion, FK filtering, and
  dedup are testable without mocking the download; `run()` is a thin wrapper.
- Whole-source replace (delete all `source='tagger_bulk'`, reinsert) rather than per-row upsert.

## Bugs
- **Aliases were silently missing.** Scryfall resolves searches like `otag:boardwipe` against a
  tag's `aliases` array — canonical `sweeper` carries "boardwipe", "mass removal", "wipe" — and
  the original ingest never read that field, so alias lookups quietly returned nothing. Caught
  by a manual user spot-check, not by the tests. Added a separate `tag_aliases` table (813
  rows) rather than inserting duplicate `card_tags` rows, an explicit user decision, so an
  alias isn't double-counted as a distinct tag in downstream clustering.
- The plan's field-name summary was stale in three ways (`label`/`slug` not `name`, no
  `category` field, `parent_ids` present so no inversion needed). Even official documented
  sources drift — check live before writing extraction code.

## Outcome
Done, 111/111 tests. Two known gaps, both flagged rather than fixed: `card_tags` stores the
slug, not the human-readable label, and tag `weight` (median/strong/very_strong) isn't stored.
Art/illustration tags live in a separate bulk file and are out of scope.
