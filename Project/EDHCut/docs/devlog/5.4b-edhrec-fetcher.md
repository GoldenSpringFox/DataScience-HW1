Date: 2026-07-31 | Status: done

Implemented `edhcut/ingest/edhrec.py` against our own cached session (not `pyedhrec`).
Live run: **1,177 `edhrec_card_stats` rows + 285 `edhrec_themes` rows**, 5/5 slots, 0 errors.

## Decisions
- **Cardlist-category precedence** (the question 5.4-A left open, decided by the user from a
  3-way choice): editorial tags win — Game Changers > High Synergy Cards > Top Cards > New
  Cards — falling back to the type-based list. EDHREC's editorial judgment about *why* a card
  matters is information our own `type_line` can't provide. Only the label is at stake; the
  `synergy`/`num_decks` numbers are identical whichever list wins.
- `commander_key` uses config order while the EDHREC URL slug is alphabetical — two
  independent identifiers, and tests assert they stay uncoupled.
- Page-shape validation raises on a missing `pageProps.data`/`container`/`panels`, but *not*
  on an empty cardlist — a thin corpus (Orysa: 7 themes) is the cold-start signal the plan
  wants surfaced, not an error.
- Reused Archidekt's `_parse_next_data`, `_resolve_local_oracle_id`, and `slot_key_for` rather
  than duplicating them — same Next.js mechanism underneath.
