## Method & design decisions
- **Environment**: the repo already has a shared venv (`venv/`, Python 3.14.4) at the
  `Homework - Group` root, used across all course subprojects — `edhcut` is editable-installed
  into it (`pip install -e ./Project/EDHCut`) rather than getting its own venv, so there's one
  environment for the whole repo. `pyproject.toml` still declares `edhcut`'s deps; only the
  ones missing from the shared venv (`requests-cache`, `tenacity`, `pyrchidekt`, `pytest`) were
  newly installed. (First pass used a separate `uv`-managed `.venv` inside `EDHCut/` —
  reverted once it became clear the repo already standardizes on one shared venv.)
- **Config as a frozen dataclass** (`Config`/`Paths`/`RateLimit` in `config.py`): mutable
  defaults (the commander-slot list, the rate-limit dict) go through `field(default_factory=...)`
  so the dataclass can stay `frozen=True` (safe to import a shared `CONFIG` singleton without
  worrying about accidental mutation). `Paths` fields are computed `@property`s off a single
  `data_dir` rather than stored separately, so there's one place to change the data root.
- **Schema**: DDL transcribed directly from plan §2.3 into `CREATE TABLE IF NOT EXISTS`
  statements (idempotency requirement from the task prompt), with `REFERENCES` foreign keys
  added between tables that share `oracle_id`/`deck_id` even though the plan's pseudo-SQL
  didn't spell them out — cheap integrity check for later ingest bugs, and `PRAGMA foreign_keys
  = ON` is set on every connection so violations actually raise.
- **HTTP client** (`http.py`): `RateLimitedSession` subclasses `requests_cache.CachedSession`
  and overrides `send()` to sleep for the per-source minimum delay *only when the request
  isn't already cached* (checked via `self.cache.contains(request=...)`, wrapped in a
  try/except so an API change in a future `requests-cache` version degrades to "always
  throttle" instead of crashing). Retry-with-backoff is a separate `request_with_retry()`
  helper (tenacity, exponential backoff, 5 attempts, retries on 429/5xx or any
  `RequestException`) rather than baked into `send()` itself — keeps the throttling and the
  retrying independently testable/swappable.
- Considered putting the retry decorator directly on `Session.send`; rejected because tenacity
  retrying `send()` would also re-trigger the cache-hit check and throttle logic on every
  retry attempt, which is the wrong behavior for a 5xx retry (should back off, not re-sleep
  the base delay each time).
- **Rate limits & cache expiry** (`RATE_LIMITS` in `config.py`): both undocumented per-request
  sources (Archidekt, EDHREC) ended up at the same settings — 2s minimum delay (double plan
  §5's "~1 req/s" tolerated floor, on the side of being gentler than strictly necessary) and a
  two-week cache expiry, chosen to be uniform across sources rather than tuned per-source, and
  short enough that a refresh run picks up updated decks/stats without much staleness. Scryfall
  keeps its own, much shorter 1-day cache and near-zero delay — it's a single bulk-file
  download, not a series of requests against someone's live endpoint, so the "politeness"
  rationale behind the other two doesn't apply; the constraint there is data freshness
  (Scryfall's bulk files update continuously), not server load.

## Impediments
None. Dependency resolution, schema creation, and session construction all worked on the
first pass. The one design risk worth flagging for later: `cache.contains(request=...)` is
part of `requests-cache`'s public `BaseCache` API but its exact signature has moved before
across major versions — if a future dependency bump breaks it, `RateLimitedSession` silently
falls back to throttling every request (including cache hits), which is safe but slower, not
a correctness bug.
