# Task 5.1 — Project scaffold + DB schema + HTTP client
Date: 2026-07-29 | Status: done

Infrastructure only: `pyproject.toml`, `edhcut/config.py`, `edhcut/db.py` (idempotent schema
creation for the plan §2.3 tables), `edhcut/http.py` (cached, rate-limited, retrying session
factory). No data ingested.

## Decisions
- One shared repo venv (`venv/` at the `Homework - Group` root) with `edhcut`
  editable-installed into it, rather than a per-project venv.
- Frozen `Config` dataclass imported as a `CONFIG` singleton; `Paths` fields are properties off
  a single `data_dir`, so there's one place to move the data root.
- Foreign keys added on top of the plan's pseudo-SQL, with `PRAGMA foreign_keys = ON` on every
  connection, so later ingest bugs surface as violations instead of orphan rows.
- Throttling and retrying kept separate: `RateLimitedSession.send()` sleeps only on cache
  misses, and `request_with_retry()` is a standalone tenacity helper. Decorating `send()`
  directly would re-sleep the base delay on every 5xx retry.
- Rate limits: 2s delay + 2-week cache for Archidekt/EDHREC (politeness toward live
  endpoints); Scryfall gets ~0 delay + 1-day cache — it's one bulk download, so the
  constraint is freshness, not server load.

## Outcome
Done, 2 tests (schema creation, idempotency). One known soft spot: `requests-cache`'s
`cache.contains()` signature has moved across major versions — if a dependency bump breaks it,
we silently degrade to throttling every request, which is slower but not incorrect.
