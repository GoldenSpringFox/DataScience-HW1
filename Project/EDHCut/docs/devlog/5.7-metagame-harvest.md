# Task 5.7 — Metagame sample harvest
Date: 2026-08-09 (harvest completed 2026-08-10) | Status: done

Not originally planned — born from 6.3's confound: synergy communities over the 5-commander
corpus recovered *the five commanders*, not card packages, because the pooled null model reads
"both cards belong to commander X's pool" as synergy. Broadening to ~1,000 commanders fixes it
at the source. Result: **996 commanders, 9,286 new decks, 13,207 total**.

## Decisions
- **Broaden the corpus instead of stratifying by slot.** A stratified estimator degenerates at
  small per-stratum sizes (as `N_s → 1` the expectation converges on the observation and the
  statistic goes to 0), so it can't combine with a wide-but-shallow sample. Stratification stays
  available for roster-scoped analyses.
- **Commander selection**: every commander with `num_decks ≥ 2,300`, uncapped — the union of
  EDHREC's 32 colour-identity pages at that threshold is *exactly* the global top-1000 (999
  distinct, no duplicates, no identity truncated), reconstructed without paginating
  `/commanders`, which only ever returns 100. An earlier per-identity cap was dropped once the
  live distribution proved already balanced.
- **Deck allocation**: `n_s = clip(round(25·√(num_decks_s / max_num_decks)), 5, 25)` — √-share
  so top commanders don't eat the budget and collapse tail coverage. ~14,900 requests, ≈8.3h at
  the unchanged 2.0s delay.
- **`-updatedAt`, not `-viewCount`** — measured live across 3 commanders: 68.0% keep rate and 0
  stale, vs 53.3% and 20 stale. `-viewCount` pulls in decks that fail the staleness check.
- **Design weights are computed at analysis time, never baked into the harvest**
  (`deck_weights.py`), so each analysis picks near-uniform or true-share deliberately.
- Roster commanders aren't re-harvested; they keep their existing full-resolution decks and
  gain only an `edhrec_num_decks` row for weighting.

## Bugs
- **The meta-sample harvester had no roster exclusion** and would have re-harvested
  Krenko/Kyler/Yenna under the `meta_sample` cohort. Caught before the real run; fixed with a
  `WHERE decks.cohort != 'roster'` upsert guard plus a regression test. The smoke test that
  "passed" simply never covered a roster commander — a test's coverage needs checking, not just
  its result.
- Archidekt's `orderBy` isn't server-validated: a nonsense value silently returns some default
  rather than erroring, so the ordering choice needed live confirmation rather than inferring it
  from the request succeeding.
- EDHREC lists partner pairs as one row with `name = "A // B"` (43/999), which collides with
  genuine DFC names — resolved whole-name-first. 999/999 resolved.
- A dense-matrix guardrail (`assert_dense_matrix_safe`, 2 GiB ceiling) was added ahead of the
  rebuild on a projected 15–22k card pool. It turned out to be a false-positive tripwire once
  the real pool size was known — resolution in `6.3-synergy-communities.md`.

## Outcome
Done, harvest run by the user. 52 new tests across the three new modules. Side effect confirmed:
`playrate.py`'s 7-of-32-colour-identities limitation is gone, all 32 now populated. Still open —
true-share weighting is not yet wired into `playrate.py`.
