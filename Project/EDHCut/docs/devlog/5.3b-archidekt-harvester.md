# Task 5.3-B — Archidekt deck harvester (run at scale)
Date: 2026-07-29 – 2026-07-30 | Status: done

## Goal & hypothesis
Implement and run the harvester designed in 5.3-A: for each of the plan's 5 configured
commander slots, collect up to `decks_per_commander` (300) valid Commander decks from
Archidekt into `decks`/`deck_cards`. "Valid" means Commander format, updated within the
staleness cutoff, the searched commander(s) confirmed via the `"Commander"` category, and
*exactly* the right physical card count once maybeboard/sideboard/token entries are excluded.

## Method & design decisions
Covered in depth in `docs/archidekt_api.md` §2.1 and §2.2 — this section summarizes what
changed at scale, in the order it was found.

**Board-membership rule went through 5 iterations before landing right** (full blow-by-blow
in `archidekt_api.md`; short version):
1. Naive "any category shared with `includedInDeck: true`" — broke on token-tracking entries.
2. Added `is_token()` exclusion.
3. Tried gating on the search-listing's own `size` field — abandoned, confirmed stale live
   (a listing said 101 while the deck's own page said 100).
4. Hardcoded "any category named maybeboard/sideboard is excluded" — overcorrected, shrank
   two real decks below their true size.
5. **Final**: only a card's *first* category decides membership (later categories are
   personal-organization tags); within that, only the literal built-in `"Sideboard"` category
   is hardcoded-excluded regardless of its own `includedInDeck` flag (Archidekt's API always
   reports it `true`, same quirk as `"Commander"`, but it's genuinely always excluded on the
   site) — `"Maybeboard"` is *not* special-cased, its own flag is authoritative. Verified
   against 4 real decks with known ground truth (one via a user-pasted actual 99-card list) —
   all 4 now compute to exactly 99.

**Partner-slot fallback** (`harvest_slot()`'s 3-pass design): Yoshimaru + Bruse Tarl has only
4 decks running the exact pair — nowhere near 300. Added a fallback: search each partner
separately with `colors=<pair's combined identity>` (`colors=WR` here), keeping decks where
just that one partner is `"Commander"`-tagged. Verified live before coding that `colors=` is
an *exact* identity match (sampled 180 results/partner: 0 off-color, 0 missing the shared
color) — so this reliably surfaces decks pairing the searched partner with some *other*
red partner (Rograkh, Kediss, Jeska, Akiri, ...), the structurally closest available
stand-ins. Remaining quota splits evenly between the two partners with rollover if one runs
dry. New `decks.slot_key` column groups these fallback decks (which run *real*, different
commanders) into the pair's corpus while `commander_oracle_id`/`partner_oracle_id` stay
truthful to what the deck actually runs.

**Bonus finding from building the fallback**: the two single-partner `colors=` searches
overlap on genuine exact-pair decks the original `cardName=`-based search had *missed*
entirely — of 32 real Yoshimaru+Bruse Tarl decks eventually found, only 4-6 were reachable via
`cardName=`, the other 26+ only surfaced via the fallback's identity-based search (spot-checked
4 directly against Archidekt, confirmed both genuinely `"Commander"`-tagged). The user's
original manual estimate ("<10 real decks") was itself an artifact of `cardName=`'s search
limitation, not the true population size.

## Evaluation & results
- All 1,230 kept decks verified to have *exactly* the right physical card count (99/98 minus
  any unresolved cards, cross-checked against the audit log for spot examples).
- 0 rows where a deck's own commander leaked into its own `deck_cards`.
- 0 duplicate `(source, source_id)` rows despite decks appearing in multiple search passes
  (dedup is by listing id, before the deck-detail fetch).
- `pytest`: 49 tests in `test_archidekt.py`/`test_archidekt_harvest.py` (73 across the whole
  package including precons), all passing against the final code.

## Interesting findings
- Unresolved-oracle-id counts (8-13 per slot) are consistent with expectations — mostly
  banned/restricted-in-Commander cards absent from `cards` by design (task 5.2's filter), not
  a resolution bug.
- `flagged` counts (19/19/0/43/6 across slots) are single-commander-mismatch or
  high-unresolved-ratio decks worth a manual look, not errors — none investigated further
  this session, available in `data/logs/archidekt_harvest_log.txt` if needed later.

## Impediments
- The maybeboard/sideboard heuristic was wrong twice in a row before landing right, each
  time because the previous "fix" had only been checked against 1-3 decks and happened to
  match them by coincidence, not because the rule was actually correct. Full postmortem in
  `archidekt_api.md` — worth internalizing before touching this logic again: a rule that
  matches every deck checked *so far* is not the same as a correct rule.

## Notes for future work
- `harvest_slot()`'s partner fallback is currently only exercised by the one real partner
  slot in `config.commander_slots` (Yoshimaru + Bruse Tarl). If more partner slots get added
  later, worth re-verifying the even-split/rollover behavior holds up with different
  exact-pair-vs-fallback ratios.
- The Krenko double-harvest (301 vs. 300) is harmless but a reminder: `-viewCount` ordering
  is not a stable sort across separate runs on a live site — don't assume re-running with the
  same parameters reproduces byte-identical results.
