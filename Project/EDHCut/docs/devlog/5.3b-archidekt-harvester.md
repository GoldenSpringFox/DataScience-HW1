# Task 5.3-B — Archidekt deck harvester (run at scale)
Date: 2026-07-29 – 2026-07-30 | Status: done

Harvested all 5 commander slots into `decks`/`deck_cards`: **1,230 decks, 97,911 card rows**
(Krenko 301, Kyler 300, Yenna 300, Orysa 29, Yoshimaru+Bruse Tarl 300). Run at scale by the
user, not by Claude. Orysa's thin 29 matches the plan's expectation for a niche commander.

## Decisions
- **Board membership**: only a card's *first* category decides whether it's in the deck (later
  ones are personal organization tags). Only the literal built-in `"Sideboard"` category is
  hardcoded-excluded regardless of its `includedInDeck` flag; `"Maybeboard"` is *not*
  special-cased — its own flag is authoritative. The search listing's `size` field is unusable
  (confirmed stale live).
- **Partner-slot fallback**: only 4 decks run the exact Yoshimaru + Bruse Tarl pair, so the
  harvester falls back to searching each partner alone with `colors=<pair identity>`, keeping
  decks where that one partner is `"Commander"`-tagged. Verified `colors=` is an exact identity
  match before relying on it. `decks.slot_key` groups these into the pair's corpus while
  `commander_oracle_id`/`partner_oracle_id` stay truthful about what the deck actually runs.

## Bugs
- **The board-membership rule was wrong twice before landing**, each time because the previous
  fix had only been checked against 1–3 decks and matched them by coincidence. Postmortem in
  `docs/archidekt_api.md`; the lesson is that a rule matching every deck checked *so far* is
  not the same as a correct rule. Final version verified against 4 decks with known ground
  truth, all computing to exactly 99.
- Krenko has 301 decks, not 300 — harvested twice, and Archidekt's `-viewCount` ordering
  shifted by one deck between runs. Harmless (upserts are idempotent), but a reminder that
  re-running against a live site does not reproduce identical results.

## Outcome
Done, 49 tests. Every kept deck verified to have exactly the right physical card count; no
commander leaks into its own `deck_cards`; no duplicate `(source, source_id)` rows. The
34 unresolved oracle ids are banned/restricted cards excluded by 5.2's filter, not
resolution bugs.

Side finding: the `colors=`-based fallback surfaced ~26 genuine exact-pair decks that the
`cardName=` search had missed entirely — the "fewer than 10 real pair decks" estimate was an
artifact of that search's limitations, not the true population.
